ReignHub uses one public service contract implemented by Go and Cloudflare Worker. Public API and behavior changes require reviewing both implementations, updating affected code and validating both deployments. Runtime details such as SQLite versus D1/Durable Objects can differ; an internal change does not require an artificial edit to the other implementation.

## Review expectations

PRs describe the problem, resulting behavior, checks actually run and remaining limits. For public service changes, explain how both runtimes satisfy the contract, including when one needs no code edit. UI changes include relevant light/dark and desktop/narrow-screen evidence. Update the corresponding knowledge page when changing a shared rule or recovery behavior.

Use isolated Agent fixtures and temporary databases. Do not change real conversations as test data. Builds, fixture tests and real vendor integration checks provide different evidence; report them separately. Existing shared smoke tests exercise both services but do not cover every endpoint or failure combination.
