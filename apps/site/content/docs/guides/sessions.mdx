## Projects and ordering

Sessions are grouped by the full working directory on the host, with recent updates first. Provider icons identify sessions from different agents in the same project. Switching projects does not change an agent's working directory.

Only ready providers accept new messages. Cached or historical sessions do not imply access to an active task owned by another independent backend.

## Live output

Long-lived connections carry incremental text. The UI uses virtual lists and Markdown rendering. Thinking appears at the start before public output. Public text replaces it; active tool operations are collapsed until expanded. Temporary activity disappears on completion.

Structured question replies render as answered cards, hiding transport fields. Completed messages support whole-message copying, timestamps and desktop hover actions. Mobile does not require hovering.

## Models, drafts and sending

Choose from models offered by the provider in the composer. The host agent determines model availability and permissions. ReignHub does not provide model access or include model subscription costs.

Desktop and Web: Enter sends, Shift + Enter adds a line. Mobile uses the send button. Unsent drafts are retained per session.

## Reconnection and caches

Native SQLite and browser IndexedDB retain synchronized content. You can read cached content offline, but cannot submit remote commands.

Reconnecting fetches current state. Gaps in incremental events trigger a snapshot before subscriptions resume. A cache is not a complete backup or a guarantee of offline access to unsynchronized history.
