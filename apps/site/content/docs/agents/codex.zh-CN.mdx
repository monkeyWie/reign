## 一个 Codex 入口

ReignHub 只显示一个 **Codex**。来自 App、CLI 或 VS Code 的会话一起按项目聚合，原始来源仍可在会话详情中查看。

1. 在被控电脑安装 Codex，确认本机使用正常。
2. 保持管理会话的应用、终端或编辑器可用。
3. 打开 ReignHub，Codex 会自动连接，开关默认开启。
4. 从侧边栏打开会话，也可以连接其他设备远程管理。

无需重启 App，也无需单独启用 CLI。在桌面系统上，实时交互需要兼容且可访问的本地 Codex 连接服务；能看到历史记录不代表当前持有者一定可连接。

## 会话归属与退出

已有会话仍交给当前持有者执行。通过 ReignHub 新建的会话使用其私有 Codex 后端。明确退出 ReignHub 会关闭该后端，可能中断由它执行的任务，但不会结束外部 Codex App、CLI 或编辑器；关闭窗口会让 ReignHub 留在托盘。

## 连接与重试

连接恢复后会重新同步当前状态。发送结果不确定时不会自动重发，请先核对会话。ReignHub 不会因为连接失败就强行接管仍被占用的会话。

Windows 的访问被拒绝提示可能指出连接服务来自 SSH 或 VS Code 环境。请按提示在对应环境关闭占用服务的实例，再重新打开桌面 Codex App 并重试。ReignHub 不会自动修改权限或结束用户进程。

## 支持边界

Codex 的本地 IPC 接口可能随版本升级变化。目前跟随会话支持状态版本 11、13，发布 ReignHub 自有状态使用版本 11。未知版本会明确报错，已保存的历史仍可通过只读接口加载。读取历史、模型列表和新建会话仍需 Codex 可执行文件，也可以使用桌面 App 内置的版本。

隔离测试验证了来源保留、路由、实时状态和失败恢复。与每种已安装 App、CLI 和 VS Code 版本的兼容性仍需实机验证。
