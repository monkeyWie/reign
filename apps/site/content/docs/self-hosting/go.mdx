## Choose Go or Cloudflare

`reignhub-server` runs independently of Cloudflare. It provides the same device pairing and encrypted connection protocol as the Worker. SQLite replaces D1, and Go WebSocket rooms replace Durable Objects. Agents stay on controlled computers; the service forwards encrypted traffic.

All features start by default: device directory, pairing, signaling, encrypted relay, Web console, UDP STUN and TCP STUN. Both Go and Worker roots redirect to `/chat/`; neither self-hosted package includes the marketing website or docs.

## One-command deployment

From the source repository root:

```sh
docker compose -f deploy/service/compose.yaml up -d --build
```

SQLite persists in a Docker volume. Open HTTP **26330/TCP** and discovery **26331/TCP + UDP**. Provide HTTPS/WSS with a reverse proxy, or use `--tls-cert` and `--tls-key`. Remote browsers need HTTPS; localhost works for browser development.

Alternatively, extract a standalone release archive for Linux, macOS or Windows (amd64/arm64), verify its SHA-256, and run `reignhub-server`. The release binary embeds the optimized Web client; no Go or Node runtime is needed.

## Configuration

Defaults are overridden by a JSON file, then by explicit CLI flags:

```sh
reignhub-server --config server.json --listen :8080 \
  --stun-listen :3478 --tcp-stun-listen :3479 \
  --state /var/lib/reignhub/reignhub.db
```

```json
{
  "http": true,
  "signal": true,
  "relay": true,
  "webEnabled": true,
  "stun": true,
  "tcpStun": true,
  "listen": ":26330",
  "state": "data/reignhub.db",
  "stunListen": ":26331",
  "tcpStunListen": ":26331"
}
```

Disable features with `--web-enabled=false`, `--relay=false`, `--stun=false` or `--tcp-stun=false`. Disabling signaling also requires disabling relay. `--http=false` runs only the selected probes and never opens SQLite, useful alongside a Worker.

Probe sockets bypass HTTP proxies/CDNs. If ports are mapped or the HTTP hostname is proxied, advertise direct endpoints with `--self-stun stun:probe.example.com:3478 --tcp-stun-public probe.example.com:3479`. Otherwise they derive from the request hostname and bound listener ports. Configure exact additional browser origins using `--origins`, public discovery using `--public-stun`, and external console assets using `--web DIR`. Run `--help` for every flag.

## Installation and upgrades

The release packaging archive contains Homebrew and Scoop definitions with verified URLs/hashes. Homebrew requires a tap: create one with `brew tap-new reignhub/local`, copy `Formula/reignhub-server.rb` into `$(brew --repository reignhub/local)/Formula/`, then run `brew install reignhub/local/reignhub-server`. Windows can use `scoop install ./bucket/reignhub-server.json`. Homebrew supports `brew services start reignhub-server`. A short tap command requires a separately published tap; package registration is not part of a source build.

For Linux, use the bundled systemd unit. Preserve the SQLite database when upgrading. Stop the service before copying the database and any WAL/SHM files, or use SQLite's backup API. The database contains the persistent service ID, signing key, device metadata, credential hashes and pairing permissions, but no chat plaintext. Check `/healthz`, `/p2p/config` and an actual paired connection after restarting.

The repository's `deploy/service/README.md` contains Docker, Nginx, systemd and installer details. Building from source with `go install` only embeds Web when release assets have been staged; use a release binary or provide `--web`.
