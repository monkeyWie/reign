## Download and start

Choose the `reignhub-server` archive for your OS and CPU from [server downloads](/download#server). Verify it against the release’s `SHA256SUMS`, extract it and enter the directory containing the executable and `config.json`. The binary embeds the Web console.

```sh
./reignhub-server --version
./reignhub-server
```

On Windows PowerShell, run `.\reignhub-server.exe`. Open `http://localhost:26330/chat/` on the server. For public browser access, proxy HTTPS to port 26330/TCP or configure `tlsCert` and `tlsKey`. Expose 26331/UDP and TCP for STUN and 26332/UDP and TCP for native relay. Behind NAT or a reverse proxy, set `selfStun`, `tcpStunPublic` and `nativeRelayPublic` to addresses reachable by clients.

To use Docker Compose, run this from the source repository:

```sh
docker compose -f deploy/service/compose.yaml up -d --build
```

## Configuration

The server reads `config.json` in the working directory. Archives include the template. With a binary-only install, run `reignhub-server --init` once in your service directory, edit the file and run `reignhub-server`. Initialization preserves existing files. Use `--config PATH` to select a different file. Relative state, Web and TLS paths resolve from the config directory.

This configuration runs TCP and UDP discovery on port 3478 on all interfaces.

```json
{
  "http": false,
  "stunListen": ":3478",
  "tcpStunListen": ":3478"
}
```

Restart the Go service after editing. A control service can use `externalStun` to append discovery nodes and `externalRelays` to register relay addresses and pins.

## Installation and upgrades

The release packaging archive contains Homebrew and Scoop definitions with verified URLs/hashes. Homebrew requires a tap: create one with `brew tap-new reignhub/local`, copy `Formula/reignhub-server.rb` into `$(brew --repository reignhub/local)/Formula/`, then run `brew install reignhub/local/reignhub-server`. Windows can use `scoop install ./bucket/reignhub-server.json`. Homebrew supports `brew services start reignhub-server`. A short tap command requires a separately published tap; package registration is not part of a source build.

For Linux, use the bundled systemd unit. Preserve the SQLite database when upgrading. Stop the service before copying the database and any WAL/SHM files, or use SQLite's backup API. The database contains the persistent service ID, signing key, device metadata, credential hashes and pairing permissions, but no chat plaintext. Check `/healthz`, `/p2p/config` and an actual paired connection after restarting.

The repository's `deploy/service/README.md` contains Docker, Nginx, systemd and installer details. Building from source with `go install` only embeds Web when release assets have been staged; use a release binary or set `web` in config.json.
