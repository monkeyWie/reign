---
title: Add a STUN and native relay node
description: Offer discovery and optional QUIC and TCP relay on a public IP.
---

## When you need it

Workers cannot listen on raw UDP/TCP probe sockets. Public UDP STUN works by default. To add your own mapping discovery or cover unreachable public probes, use `{"services":{"stun":{}}}` as the public server’s `config.json`.

The probe returns address mappings only. It does not store a device directory, run agents, serve Web pages or relay application traffic. You can deploy the Worker without it.

## Build and run

Use the Go version in `go.mod`, or the server archive for your platform:

```sh
go build -o reignhub-server ./cmd/reignhub-server
# Set config.json to {"services":{"stun":{}}} before starting.
./reignhub-server
```

Allow both in the server firewall and cloud security group:

| Port  | Protocol | Purpose                                    |
| ----- | -------- | ------------------------------------------ |
| 26331 | UDP      | STUN Binding / mapped-address discovery    |
| 26331 | TCP      | Native TCP probe and hole-punch candidates |

An ordinary Nginx HTTP proxy cannot forward these protocols. Use **DNS only** for the probe hostname, without Cloudflare's HTTP proxy.

## Publish endpoints from the Worker

Set Worker variables and redeploy:

```text
EXTERNAL_STUN=["probe.example.com:26331"]
```

Clients still configure only the Worker HTTPS URL. `/p2p/config` publishes these endpoints.

Put public and self-hosted nodes in the same list. The control service always advertises Cloudflare, Google and Bilibili (`stun.chat.bilibili.com:3478`) for UDP discovery. Omit the list or use `[]` to add no other nodes. A Go control service uses `services.control.stunServers` with the same values and also publishes its local STUN listeners. Browsers have no raw TCP API; TCP probing is primarily for native clients.

## Add native relay on the same machine

Enable STUN and relay in the node’s `config.json`. Start the node, then run the second command from the same directory in another shell to read its private registration credential.

```json
{
  "services": { "stun": {}, "relay": {} }
}
```

```sh
./reignhub-server
./reignhub-server --print-relay-credential
```

Allow inbound UDP and TCP on port 26332. Keep the node database on a persistent volume so its credential survives restarts and upgrades. In the Worker dashboard, create a **Secret** named `EXTERNAL_RELAYS` and paste the array below with your address and credential. With Wrangler, run `pnpm exec wrangler secret put EXTERNAL_RELAYS` and paste it at the prompt. For Go control, set `services.control.externalRelays` to the same array and restrict access to the configuration file. Clients receive the public TLS pin and a short-lived access ticket.

```json
[{ "addresses": ["203.0.113.10:26332"], "credential": "REPLACE_WITH_NODE_CREDENTIAL" }]
```

For multiple nodes, add one entry per relay. A shared address advertises both protocols. Use `["udp:probe.example.com:3478","tcp:probe.example.com:3479"]` for separate endpoints. This syntax applies to both STUN and each relay’s `addresses` array on Go and Worker. Redeploy the Worker or restart the Go control after editing its configuration.

## Limits

Symmetric NAT, carrier networks and enterprise firewalls may still block hole punching. A probe does not guarantee direct access. When direct access is unavailable, the Worker encrypted WebSocket relay provides a fallback path.
