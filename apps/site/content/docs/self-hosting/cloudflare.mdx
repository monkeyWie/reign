## Deployment button

Open [Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/monkeyWie/reign), authorize your Cloudflare account and follow the setup flow.

Deploy the **root repository, not only `apps/site`**: the site depends on the connection core and SDK in the same pnpm workspace. Provision a Worker, one D1 database and a SQLite Durable Object.

Automatic resource configuration is prepared in the repository. The complete authorization and setup flow still needs to be completed and verified in your own account.

## Manual deployment

Install Git, Node.js 24 and pnpm 10.34.5, and prepare a Cloudflare account:

```sh
git clone https://github.com/monkeyWie/reign.git
cd reign
corepack enable
pnpm install --frozen-lockfile
pnpm exec wrangler login
pnpm build:web
pnpm run deploy
```

Use `pnpm run deploy`, not pnpm's own deploy subcommand. The deployment script initializes D1 after resource creation; requests may fail until initialization completes.

## Preserve resource bindings

Save the assigned D1 database ID in `wrangler.jsonc`. Reuse that database for future releases so that the device directory and service identity remain intact.

Check the service:

```sh
curl https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/healthz
curl https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/p2p/config
```

Health should succeed and config should contain connection capabilities and the signing identity. Open the same-origin `/chat` page and set the Worker root URL in native clients.

## Domains and origins

Bind a custom domain in Cloudflare and use HTTPS after DNS and certificate activation. Keep Web, API, signaling and relay on the same origin.

To allow additional Web origins, set `ALLOWED_ORIGINS` to exact comma-separated origins. The current origin is allowed by default. Broad wildcards are not a replacement for pairing authorization.

## Site languages and SEO

The website and docs are available at `/en` and `/zh-CN`; `/chat` keeps its stable console route. Before building for a stable public domain, set `SITE_URL`:

```sh
SITE_URL=https://reign.example.com pnpm build:web
pnpm run deploy
```

This generates canonical URLs, language alternates, social cards and a sitemap for **your** domain. Without `SITE_URL`, the build omits absolute canonical URLs and publishes an empty sitemap rather than pointing your instance at the official site. Change the build variable and rebuild if you change domains. Keep private instances protected by access control; robots.txt is not authorization.

## Local verification

```sh
pnpm exec wrangler d1 migrations apply DB --local
pnpm exec wrangler dev --port 8787
```

Open `http://localhost:8787/chat`. Local resources are separate from production D1; never point development at a real user's device state directory.
