## Native UI: NSGo

Desktop and mobile UI is written in Go with NSGo and mapped to platform-native views. Device navigation, virtual session lists, Markdown and image previews use native UI.

Native views avoid bundling a browser runtime, but package size still depends on architecture, system libraries, signing and build options. The browser product now uses React, not a distributed NSGo WASM console.

## Application and providers: Go

Go shares device management, cryptography, networking and agent adaptation. Providers isolate Codex launch details and native protocols. The app calls Go logic directly instead of adding a separate UI-to-daemon layer.

## Networking: WebRTC, native TCP and WebSocket

Native WebRTC uses Pion. Browsers use RTCPeerConnection and DataChannel without Go WASM. Native clients also implement TCP candidate discovery and hole punching.

WebSockets serve signaling and encrypted traffic relay. Optional STUN discovers address mappings. No TURN, DERP or cloudflared tunnel is required.

## Web: Next.js, React and OpenNext

The website, docs and `/chat` share Next.js App Router. The React controller uses virtual messages and incremental synchronization. OpenNext adapts builds to Workers; clients default to the current page origin.

Fumadocs generates pages, navigation, search and pagination from repository MDX. English and Simplified Chinese each have real content and a language-specific search filter. No separate CMS or docs service is needed.

## Storage: SQLite, IndexedDB and D1

- Native: SQLite for settings and session caches; attachment files on local disk.
- Browser: IndexedDB for pairing identity, session snapshots and bounded attachment caches.
- Worker: D1 for service metadata; the official business layer uses Drizzle ORM for accounts, plans and orders.
- Existing Go storage uses SQLite, with GORM on some service paths. Cloud D1 and local ORM are separate systems.

## Official business layer

Better Auth integrates GitHub/Google and Waffo handles payments. The server verifies entitlements. Actual provider availability, products and prices follow live service configuration. Open-source deployments do not require this layer.

## Dependencies and versions

Pinned versions are in `go.mod`, `clients/nsgo/go.mod`, `package.json` and `pnpm-lock.yaml`. NSGo is a newer framework; upgrades require platform builds and UI regression checks. See [Contributing](/docs/contributing).
