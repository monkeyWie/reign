## 测试结果

原生 UI 与 Go 核心在同一应用进程中运行，把更多资源留给执行任务的 Agent。

| 测试项目                 | 结果         |
| ------------------------ | ------------ |
| macOS arm64 压缩下载体积 | **8.9 MB**   |
| macOS .app 大小          | **23.1 MB**  |
| 演示本机面板空闲内存     | **39.5 MiB** |
| 打开演示会话后的内存     | **48.4 MiB** |

## 测试环境与方法

测试于 2026-11-14，设备为 Apple M5，运行 macOS 26.6，arm64 架构，使用标准优化的预览构建。

**内存测试**：在隔离演示模式下启动 ReignHub，预热一分钟，分别测量本机面板与包含 Markdown、代码块和表格的演示会话。通过 `vmmap` 采集 ReignHub 应用进程的物理内存占用，每个场景采样 5 次，间隔 2 秒，取中位数。

**体积测试**：统计完整 `.app` 内的文件大小，并使用 tar.gz 压缩完整应用，测量下载体积。

## 轻量的技术基础

- **NSGo 原生视图**：直接使用平台 UI，无需打包浏览器运行时。
- **Go 应用核心**：设备管理、网络、缓存与 Provider 在应用内直接调用。
- **虚拟消息列表与增量更新**：按需渲染会话内容，流式更新消息。
