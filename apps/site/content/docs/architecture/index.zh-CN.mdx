## 整体架构

ReignHub 将使用界面、连接协调和 Agent 执行分开：你从任意设备发出指令，Agent 在自己的电脑上完成工作。

## 原生应用

桌面与移动端采用 NSGo 原生视图，Go 在同一应用进程中处理设备管理、配对、网络、会话缓存与 Provider。原生应用无需内嵌浏览器运行时，带来轻巧的安装包与低内存占用。[查看性能实测](/docs/architecture/performance)。

桌面应用同时承担控制端和被控端：既能连接其他电脑，也能向已授权设备开放本机 Agent。移动端作为控制端。

## Web 与连接服务

Next.js 与 React 提供官网、文档和浏览器控制台，通过 OpenNext 部署到 Cloudflare Worker。连接服务负责设备发现、配对信令和加密中继。

- **Durable Objects**：管理设备房间、在线连接与 WebSocket 信令。
- **D1**：保存设备身份、配对关系和服务元数据。
- **端到端加密**：会话与附件在设备上解密，中继转发密文。

## 直连优先

客户端收集局域网、IPv6 与 STUN 候选地址。原生端探索 UDP 和 TCP 路径，浏览器使用 WebRTC。直连成功后，业务数据直接在设备间流动；直连不可用时，可使用服务提供的加密中继。

可选 Go 探测器在公网同一端口提供 TCP／UDP 探测，入口由服务统一下发。[了解连接策略](/docs/guides/connections)。

## Agent 接入

Provider 将各 Agent 的原生接口转换为统一的会话、消息、模型与附件能力。Codex App 与 CLI 通过各自的 Provider 接入，用户在项目列表中统一管理会话。[了解 Agent 接入](/docs/agents)。

## 选择部署方式

使用官方服务可集中管理账号与设备；也可以部署自己的 Worker，使用相同的客户端、连接协议和加密能力。[部署自己的服务](/docs/self-hosting)。
